     1→# NEONFALL — Projekt-Worklog
     2→
     3→## Projekt-Status (aktuell)
     4→
     5→NEONFALL ist eine vollwertige, fertige Tetris-Web-App (Neon-Stil, deutsche UI,
     6→Touch- + Tastatursteuerung, Hold/Next, Momentum-Drop, integrierte Musik +
     7→synth. SFX). Das eigentliche Spiel stammt aus einer vom Nutzer gelieferten
     8→einzelnen HTML-Datei (`upload/neonfall-10.html`) und ist **stilistisch und
     9→spieltechnisch unverändert** belassen worden.
    10→
    11→Die Aufgabe war ausschließlich, diese HTML in eine echte **installierbare
    12→PWA-App** (Next.js) zu überführen und das **CORS/Musik-Problem am Handy** zu
    13→lösen. Beides ist umgesetzt und verifiziert.
    14→
    15→## Architektur / Key Decisions
    16→
    17→- **Spiel-Code preservation**: CSS (16 KB), Body-HTML (4.4 KB) und JS-IIFE
    18→  (34.5 KB) wurden 1:1 aus der Original-HTML extrahiert (`scripts/extract.js`)
    19→  und als escapte Template-Literals in `src/app/neonfall-content.ts` abgelegt.
    20→  So ist sichergestellt, dass keinerlei Spiellogik/Styling angefasst wird.
    21→- **`src/app/page.tsx`** (Client-Komponente):
    22→  - Injiziert die Original-CSS via `<style dangerouslySetInnerHTML>`.
    23→  - Rendert den Original-Body als **JSX** (class→className, for→htmlFor,
    24→    value→defaultValue bei Range-Slidern, um React-Warnungen zu vermeiden —
    25→    verhaltenserhaltend). JSX statt Wrapper-Div, damit die `body`-Flex-Layout-
    26→    Regeln der Original-CSS exakt greifen (Elemente sind direkte Body-Kinder).
    27→  - Führt das Original-IIFE in `useEffect` per injected `<script>`-Tag aus
    28→    (läuft einmal dank `initRef`-Guard; `reactStrictMode:false` im next.config
    29→    verhindert Dev-Double-Invoke).
    30→  - Registriert den Service Worker (`/sw.js`).
    31→- **`src/app/layout.tsx`**: Minimal, nur PWA-Metadaten (manifest, theme-color
    32→  #0a0a14, apple-mobile-web-app-capable, viewport-fit=cover, user-scalable=no)
    33→  + Google-Fonts (Space Grotesk, JetBrains Mono) als `<link>` (damit die
    34→  Font-Namen aus der Original-CSS erhalten bleiben). Kein Geist-Font, keine
    35→  Toaster, kein Wrapper — Body enthält direkt `{children}`.
    36→- **Musik (CORS-Fix)**: `neonfall-music.mp3` liegt in `public/`. Das Spiel
    37→  macht `fetch('neonfall-music.mp3')` → relativ zu `/` → `/neonfall-music.mp3`
    38→  → same-origin (Next.js serviert `public/`), **kein CORS mehr**. Am Handy
    39→  (wo die Datei vorher via `file://` oder falschem Host geladen wurde) lädt
    40→  sie jetzt zuverlässig.
    41→- **PWA**: `public/manifest.json` (name NEONFALL, standalone, portrait,
    42→  icons 192/512 any+maskable). `public/sw.js` precacht App-Shell + Musik,
    43→  cache-first für Same-Origin-Assets, SWR für Cross-Origin (Fonts). Dadurch
    44→  installierbar (Android Chrome + iOS Add-to-Home-Screen) **und offline-
    45→  fähig**.
    46→- **Icons**: Via image-generation Skill ein 1024×1024 Neon-Tetris-Icon
    47→  generiert, mit sharp auf 512/192/180/32 resized (`icon-512/192.png`,
    48→  `apple-touch-icon.png`, `favicon.png`).

   304→## Nutzer-Feedback: 3 Probleme (Musik-Ladezeit, Hinweis-Layout, Desktop-Breite)
   305→
   306→**Task ID:** UF-1 · **Agent:** main (Nutzer-Anfrage, Vorrang vor Cron)
   307→
   308→### Problem 1: Musik dauert lange bis sie beginnt
   309→**Ursache:** Das Spiel fetcht `neonfall-music.mp3` (16 MB) erst bei der ersten
   310→Nutzer-Interaktion (`initAudio`), dann `decodeAudioData`. Auf dem Handy heißt
   311→das: 16 MB Download über mobiles Netz + Decode = mehrere Sekunden Wartezeit.
   312→
   313→**Fix:** `<link rel="preload" href="/neonfall-music.mp3" as="fetch" crossorigin>`
   314→in `layout.tsx` head. Der Browser startet den Download sofort beim Seitenladen
   315→(hohe Priorität), während der Nutzer den Hinweis liest. Beim ersten Tap ist die
   316→Datei bereits im HTTP-Cache → `fetch()` im Spiel liefert sofort, nur noch
   317→Decode (~100 ms).
   318→
   319→**Verifiziert:** Resource-Timing zeigt `initiator:link, startTime:89ms,
   320→duration:140ms, decodedMB:16.02` — Preload läuft sofort. Nach `initAudio`:
   321→`musicTransferKB:0` (aus Cache) — Musik startet innerhalb ~100 ms. ✓
   322→
   323→**Offen (6-Track-Crossfade):** Nutzer erwähnt 6 einzelne Musikdateien, die
   324→gefadet werden sollen. Dateien noch nicht hochgeladen → kann noch nicht
   325→implementiert werden. Wurde vom Nutzer angefragt; auf Upload wartend.
   326→
   327→### Problem 2: Hinweis-Overlay zweispaltig (sieht schlecht aus)
   328→**Ursache:** Original-Game-CSS hat `@media (min-width: 700px) {
   329→.hint-cols-wrap { display: flex; gap: 24px; } }` → auf Desktop/Breitbild werden
   330→Touch- und Tastatur-Anleitung nebeneinander gezeigt. Nutzer sagt: „war so auch
   331→nicht" (soll einspaltig sein).
   332→
   333→**Fix:** Shell-CSS-Override (injected nach Game-CSS):
   334→`.hint-cols-wrap { display: flex !important; flex-direction: column !important;
   335→gap: 16px !important; }` → Touch und Tastatur stapeln sich immer vertikal.
   336→
   337→**Verifiziert:** `hintColsWrapDirection:column` ✓. VLM: „single vertical column
   338→(stacked)... no longer split into two side-by-side columns... highly readable,
   339→well-spaced... no significant layout problems."
   340→
   341→### Problem 3: Desktop-App zu breit

   513→### Problem 1: Next-Box war komplett leer
   514→**Ursache (gefunden via Code-Inspektion):** In `drawNext()` wurden
   515→`offsetX`/`offsetY` in **Pixeln** berechnet (`centerX - pieceW/2` etc.),
   516→aber dann an `drawCell(ctx, x + offsetX, y + offsetY, ...)` übergeben.
   517→`drawCell` macht intern `px = x * size` — multipliziert also den Offset
   518→nochmal mit der Zellgröße. Bei einem I-Stein (4 Zellen breit, size=9)
   519→landeten die Zellen bei `px = (0 + 86) * 9 = 774px` in einem 120px-Canvas.

   521→
   522→**Fix:** Pixel-Offsets vor dem `drawCell`-Aufruf durch `size` teilen, um
   523→sie in Zell-Einheiten zurückzuwandeln:
   524→```js
   525→const offsetX_cells = offsetX_px / size;
   526→const offsetY_cells = offsetY_px / size;
   527→drawCell(nextCtx, x + offsetX_cells, y + offsetY_cells, ...);
   528→```
