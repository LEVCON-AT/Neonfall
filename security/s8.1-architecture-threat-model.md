### 1.2 Komponenten-Trennung

| Komponente | Trennung | Status | Risiko |
|-----------|----------|--------|--------|
| Frontend | Next.js (Port 3003) | ✅ Getrennt | Niedrig |
| Backend | Next.js API Routes + socket.io (3004) | ⚠️ Monolithisch | Niedrig |
| Datenbank | SQLite file (lokal) | ✅ Nicht öffentlich | Sehr niedrig |
| Redis | Nicht verwendet | n/a | n/a |
| Matchmaking | socket.io in-memory | ⚠️ Keine Persistenz | Mittel (Restart = Match-Verlust) |
| Firewall | UFW (ssh/80/443) | ✅ Aktiv | Niedrig |
| Reverse Proxy | nginx | ✅ Aktiv | Niedrig |
| TLS | Let's Encrypt | ✅ Auto-renewal | Sehr niedrig |
| WAF | Nicht vorhanden | ❌ Fehlt | Mittel |
| SSH | Key-only | ✅ Aktiv | Sehr niedrig |

### 1.3 Netzwerk

```
Öffentliche Ports:
  22   → SSH (key-only, fail2ban)
  80   → HTTP (redirect zu 443)
  443  → HTTPS (nginx)

Interne Ports (nur 127.0.0.1):
  3003 → Next.js (neonfall.service)
  3004 → socket.io (neonfall-multiplayer.service)
  3000-3002 → Andere Services (levcon.ai etc.)

Datenbank:
  SQLite file → kein Port, nicht öffentlich zugänglich ✅
```

### 1.4 Schwachstellen in der Architektur

1. **Keine WAF** — nginx hat Rate-Limiting aber keine Web Application Firewall
2. **Matchmaking nicht persistent** — socket.io in-memory, Restart verliert alle Matches
3. **Monolithisches Backend** — Next.js API + socket.io auf gleichem Server
4. **SQLite** — Gut für kleine Last, aber keine Replikation/HA
5. **Kein CDN** — Static assets über nginx, kein Cloudflare/CDN

### 1.5 Empfehlungen

| # | Maßnahme | Priorität | Aufwand |
|---|----------|-----------|---------|
| 1 | Cloudflare vor nginx (WAF + DDoS + CDN) | Hoch | Klein |
| 2 | Redis für Matchmaking-Persistenz | Mittel | Mittel |
| 3 | PostgreSQL statt SQLite (für Scale) | Niedrig | Groß |
| 4 | Separater Multiplayer-Server | Niedrig | Mittel |

## 2. Threat Modeling (STRIDE)

### 2.1 System-Komponenten

| Komponente | Trust-Level | Angriffsfläche |
|-----------|-------------|----------------|
| Browser (Client) | Nicht vertrauenswürdig | XSS, localStorage, DevTools |
| nginx (Reverse Proxy) | Vertrauenswürdig | DDoS, Config-Errors |
| Next.js API | Halb vertrauenswürdig | Input-Validation, Rate-Limit |
| socket.io Backend | Halb vertrauenswürdig | WebSocket-Injection, Flood |
| SQLite DB | Vertrauenswürdig | Nur lokal, nicht öffentlich |
| Service Worker | Client-seitig | Cache-Poisoning |

### 2.2 STRIDE-Analyse

#### S — Spoofing (Identitätstäuschung)

| Bedrohung | Aktuell | Gegenmaßnahme | Status |
|-----------|---------|---------------|--------|
| Gefälschte Player-ID | localStorage `p_<random>` | Server validiert nicht | ❌ Offen |
| Multiplayer-Identitäts-Spoofing | socket.io anonymous | Keine Auth | ❌ Offen |
| API-Aufruf als anderer User | Name + Player-ID frei wählbar | Keine Verifikation | ❌ Offen |

**Maßnahmen:**
- Player-ID mit HMAC signieren (Server-Secret)
- Optional: NextAuth.js für echte Authentifizierung
- socket.io: Player-ID als Query-Param + Server-Validierung

#### T — Tampering (Datenmanipulation)

| Bedrohung | Aktuell | Gegenmaßnahme | Status |
|-----------|---------|---------------|--------|
| Gefälschte Scores | POST /api/scores ohne Auth | Rate-Limit + Zod | ⚠️ Teilweise |
| Spiel-Manipulation | IIFE client-side | Nicht verhinderbar | ❌ Offen |
| Multiplayer-Cheat | Client sendet Board, Server forwarded | Server nicht autoritativ | ❌ Offen |
| DB-Manipulation | SQLite file | Nur lokal, Prisma parametrisiert | ✅ Geschützt |

**Maßnahmen:**
- Server-side Score-Plausibilitätscheck (Score vs. Zeit vs. Lines)
- Multiplayer: Server validiert Garbage-Counts
- Replay-Protection für socket.io-Events

#### R — Repudiation (Abstreitbarkeit)

| Bedrohung | Aktuell | Gegenmaßnahme | Status |
|-----------|---------|---------------|--------|
| Score-Abstreitung | Kein Audit-Log | Logging nötig | ❌ Offen |
| Multiplayer-Verhalten | Keine Logs | socket.io logging | ❌ Offen |

**Maßnahmen:**
- API-Request-Logging (IP, Player-ID, Endpoint, Timestamp)
- socket.io Connection-Logging

#### I — Information Disclosure (Informationslecks)

| Bedrohung | Aktuell | Gegenmaßnahme | Status |
|-----------|---------|---------------|--------|
| Stacktraces in Production | Next.js production mode | ✅ Geschützt |
| Secrets im Code | PAT bereinigt | ✅ Geschützt |
| DB-Pfad öffentlich | SQLite lokal | ✅ Geschützt |
| API-Error-Messages | Strukturierte JSON errors | ✅ Geschützt |
| localStorage-Daten | Player-ID, Name, Settings | ⚠️ Lesbar via DevTools |

**Maßnahmen:**
- Keine sensiblen Daten in localStorage
- CSP-Headers prüfen (schon vorhanden)

#### D — Denial of Service

| Bedrohung | Aktuell | Gegenmaßnahme | Status |
|-----------|---------|---------------|--------|
| HTTP-Flood | nginx Rate-Limiting (10r/s) | ✅ Teilweise |
| WebSocket-Flood | boardThrottle (10/sec) | ⚠️ Teilweise |
| DDoS | UFW + nginx | ⚠️ Keine DDoS-Protection |
| DB-Exhaustion | SQLite file | ⚠️ Kein Connection-Pool |

**Maßnahmen:**
- Cloudflare (DDoS + WAF) vor nginx
- socket.io: maxPayload + connection-limit
- Connection-Timeout für idle sockets

#### E — Elevation of Privilege

| Bedrohung | Aktuell | Gegenmaßnahme | Status |
|-----------|---------|---------------|--------|
| Admin-Zugang | Keine Admin-Funktion | n/a | ✅ n/a |
| Server-Compromise | systemd isoliert Services | ✅ Teilweise |
| Container-Escape | Keine Container | n/a | ✅ n/a |

**Maßnahmen:**
- systemd Hardening bereits vorhanden (NoNewPrivileges, ProtectHome, etc.)
