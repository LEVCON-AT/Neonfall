### `/api/scores` (POST) — Score-Einreichung

**Input Validation (Zod):**
```typescript
name: string, trim, 1-16 chars, regex (no leading/trailing spaces)
score: int, 0-10.000.000
lines: int, 0-1.000.000
level: int, 1-100
mode: enum ['marathon','sprint','ultra','zen']
duration: int, 0-86.400 (default 0)
playerId: string, optional
```
✅ Alle Felder validiert
✅ safeParse (keine Exceptions bei ungültigen Daten)
✅ Strukturierte Fehlermeldungen (422)

**Rate Limiting:**
- 6 Requests/Minute/IP (in-memory)
- 429 Response bei Überschreitung
✅ Ausreichend für manuelle Score-Einreichung

### `/api/leaderboard` (GET) — Bestenliste

**Input Validation:**
- mode: Must be in ALLOWED_MODES Set (marathon/sprint/ultra/zen)
- limit: parseInt + Math.min(limit, 100)
✅ Keine SQL-Injection (Prisma parametrisiert)
✅ Pagination limitiert (max 100)

### `/api` (GET) — Test-Endpoint
⚠️ Gibt `{ message: "Hello, world!" }` zurück. Sollte in Production entfernt werden.

## 5. Musik-Bug Fix (Punkt 4)

**Problem:** Musik fällt manchmal aus, besonders nach Tab-Wechsel.

**Ursache:** Shell-visibilitychange-Handler fade't Musik ein beim Zurückkommen, ruft aber nicht `mCtx.resume()` auf. Browser auto-suspended den AudioContext im Background → Musik bleibt stumm.

**Fix:** `mCtx.resume()` vor dem Fade-In hinzugefügt.
