## 1. Chaos Testing

### Test-Szenarien (dokumentiert, auf VPS manuell durchführbar)

| Szenario | Befehl | Erwartetes Verhalten | Status |
|----------|--------|---------------------|--------|
| DB aus | `systemctl stop neonfall` → DB-File rename → start | API returns 500, Seite lädt, Spiel läuft (client-side) | ✅ Dokumentiert |
| MP-Service aus | `systemctl stop neonfall-multiplayer` | Multiplayer-Dialog zeigt "Verbindung fehlgeschlagen", Solo-Spiel funktioniert | ✅ Dokumentiert |
| Netzwerk weg | Browser offline | Spiel läuft (IIFE client-side), Musik stoppt, Score wird nicht gesendet | ✅ Dokumentiert |
| Server Neustart | `reboot` | systemd startet neonfall + neonfall-multiplayer automatisch (Restart=always) | ✅ Dokumentiert |
| Internet langsam | DevTools throttling | Spiel läuft normal, API-Calls dauern länger, Leaderboard lädt langsam | ✅ Dokumentiert |

### Recovery-Verhalten
- **DB aus:** Spiel läuft client-side, Score-Submit gibt 500, Leaderboard lädt nicht → graceful degradation ✅
- **MP aus:** Multiplayer-Dialog zeigt Fehler-Toast, Solo-Spiel unbeeinträchtigt → graceful degradation ✅
- **Reboot:** Alle Services starten via systemd automatisch → auto-recovery ✅

## 2. Multiplayer Debug

### Problem: "Multiplayer-Service nicht erreichbar"

**Ursache:** MP-Service (neonfall-multiplayer) war nicht gestartet/aktiviert auf VPS.

**Lösung (auf VPS auszuführen):**
```bash
systemctl enable neonfall-multiplayer
systemctl start neonfall-multiplayer
systemctl status neonfall-multiplayer
journalctl -u neonfall-multiplayer -n 20
```

**systemd-Service robuster gemacht:**
- Fallback-Kommentar für Node.js hinzugefügt (falls bun nicht verfügbar)
- Deploy-Scripts bereits korrekt (install + restart MP)

## 3. Staging Pipeline

### Architektur
```
GitHub (main) → Production (neonfall.levcon.ai, Port 3003/3004)
GitHub (staging) → Staging (staging.neonfall.levcon.ai, Port 3005/3006) [geplant]
```

### Staging-Setup (für zukünftige Umsetzung)

| Komponente | Production | Staging |
|-----------|------------|---------|
| Domain | neonfall.levcon.ai | staging.neonfall.levcon.ai |
| Next.js Port | 3003 | 3005 |
| MP Port | 3004 | 3006 |
| systemd Service | neonfall.service | neonfall-staging.service |
| DB | /var/www/neonfall/db/ | /var/www/neonfall-staging/db/ |
| nginx config | neonfall.levcon.ai.conf | staging.neonfall.levcon.ai.conf |

### Promotion-Workflow
1. Code auf `staging` Branch → Auto-Deploy auf Staging
2. Manuelle Tests auf staging.neonfall.levcon.ai
3. Merge `staging` → `main` → Auto-Deploy auf Production
4. Bei Fehlern: Rollback via vps-update.sh Backup

### Implementierung (für nach S8.15)
1. `deploy/systemd/neonfall-staging.service` erstellen
2. `deploy/nginx/staging.neonfall.levcon.ai.conf` erstellen
3. GitHub Actions: `staging` branch → Staging-Deploy
4. DNS: `staging.neonfall.levcon.ai` → VPS-IP

**Priorität:** Mittel (aktuelles Setup mit main→production funktioniert, Staging ist Nice-to-have)
