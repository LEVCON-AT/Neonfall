## 2. Container Security

### Aktuelle Architektur: Keine Docker-Container
NEONFALL nutzt **systemd-Services** statt Docker:
- `neonfall.service` (Next.js, Port 3003)
- `neonfall-multiplayer.service` (socket.io, Port 3004)

### systemd Hardening (bereits vorhanden)
```ini
# Aus deploy/systemd/neonfall.service
NoNewPrivileges=true
PrivateTmp=true
ProtectHome=true
ReadWritePaths=/var/www/neonfall
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
RestrictRealtime=true
RestrictSUIDSGID=true
LockPersonality=true
MemoryMax=512M
CPUQuota=80%
```

### Empfehlung: Keine Containerisierung nötig
- systemd bietet vergleichbare Isolation wie Docker
- Weniger Komplexität (kein Docker-Image-Management)
- Falls Docker gewünscht: Non-root User + Read-only FS + Trivy Scan in S8.14
