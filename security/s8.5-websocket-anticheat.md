### Rate-Limiting Middleware
```typescript
socket.use((packet, next) => {
  if (socketRateLimited(socket.id)) {
    socket.emit('error', 'Too many messages. Slow down.')
    return
  }
  next()
})
```
Gilt für **alle** Socket-Events (room:create, room:join, game:lines, game:board, etc.)

## 2. Anti-Cheat — Server-side Score-Plausibilitätscheck

### Implementierte Checks (in `/api/scores` POST)

| Check | Regel | Status |
|-------|-------|--------|
| Max Score | score ≤ 2.000.000 (generous) | ✅ |
| Score-Lines Ratio | score ≤ lines × 50.000 | ✅ |
| Duration Plausibility | duration ≥ lines × 500ms | ✅ |

### Beispiel-Blockierungen
- score=99.999.999 → "Score ist unrealistisch hoch" (422)
- score=500.000, lines=1 → "Score-Linien-Verhältnis ist unrealistisch" (422)
- duration=1000ms, lines=40 → "Spieldauer ist zu kurz" (422)

### Was NICHT server-side geprüft wird (Client-trusted)
- Spiel-Logik (Piece-Positionen, Rotationen, Line-Clears) → client-side IIFE
- Multiplayer-Garbage → Client sendet line-counts, Server forwarded
- Board-State → Client sendet, Server forwarded (nicht autoritativ)

**Empfehlung für Zukunft:** Autoritativer Server für Multiplayer (S8.13 Pentest)
