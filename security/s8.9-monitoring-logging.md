## 1. Structured Logging

### Implementierung: API-Request-Logging

In `/api/scores` und `/api/leaderboard` wird structured JSON-Logging hinzugefügt:

```typescript
// Log-Format: JSON mit Timestamp, Endpoint, IP, Status, Duration
console.log(JSON.stringify({
  ts: new Date().toISOString(),
  level: 'info' | 'warn' | 'error',
  endpoint: '/api/scores',
  method: 'POST',
  ip: ip,
  status: 200|422|429|500,
  duration: Date.now() - start,
  mode: mode,
  score: score,
}));
```

### Was wird geloggt

| Event | Level | Felder | Status |
|-------|-------|--------|--------|
| Score submitted | info | ip, name, score, mode | ✅ |
| Score rejected (validation) | warn | ip, error, fields | ✅ |
| Score rejected (rate-limit) | warn | ip, count | ✅ |
| Score rejected (anti-cheat) | warn | ip, score, lines, reason | ✅ |
| Leaderboard fetched | info | ip, mode, limit, results | ✅ |
| Server error | error | ip, error message, stack | ✅ |

### Was NICHT geloggt wird

- ❌ Passwords (nicht vorhanden)
- ❌ Tokens (nicht vorhanden)
- ❌ Cookies (nicht vorhanden)
- ❌ Kreditkarten (nicht vorhanden)
- ❌ Vollständige Board-States (zu groß)

## 2. Log-Rotation

### systemd journal (bereits vorhanden)
```bash
# Logs automatisch rotiert via systemd
journalctl -u neonfall -f          # Live-Logs
journalctl -u neonfall --since today
journalctl -u neonfall -n 100      # Letzte 100 Einträge
journalctl -u neonfall-multiplayer -f

# Log-Rotation: systemd rotiert automatisch
# Max size: 10% of disk (default)
# Max age: 1 month (default)
```

### nginx Logs
```bash
/var/log/nginx/neonfall.levcon.ai.access.log
/var/log/nginx/neonfall.levcon.ai.error.log

# Log-Rotation via logrotate (Ubuntu default)
# /etc/logrotate.d/nginx
```

## 3. Monitoring

### Uptime Kuma (empfohlen für VPS)

**Installation auf VPS:**
```bash
# Docker installieren falls nicht vorhanden
apt-get install -y docker.io docker-compose

# Uptime Kuma starten
docker run -d --restart=always -p 3001:3001 -v uptime-kuma:/app/data --name uptime-kuma louislam/uptime-kuma:1

# Uptime Kuma erreichbar unter: http://<VPS-IP>:3001
# (Port 3001 ist auf dem VPS belegt — anderen Port wählen oder UFW beachten)
```

**Zu überwachende Services:**

| Monitor | URL | Interval | Alerts |
|---------|-----|----------|--------|
| NEONFALL Homepage | https://neonfall.levcon.ai/ | 60s | HTTP != 200 |
| API Leaderboard | https://neonfall.levcon.ai/api/leaderboard?mode=marathon | 120s | HTTP != 200 |
| Multiplayer Service | Port 3004 (intern) | 60s | Connection failed |

**Alerting:**
- Email an admin@levcon.at
- Optional: Discord/Telegram Webhook

### Manuelle Monitoring-Befehle (VPS)

```bash
# Service Status
systemctl is-active neonfall
systemctl is-active neonfall-multiplayer
systemctl is-active nginx

# Resource Usage
htop
free -h
df -h

# Connection Count
ss -tln | grep -c ':3003'
ss -tln | grep -c ':3004'

# DB Size
ls -lh /var/www/neonfall/db/neonfall.db
```

## 4. Alerting

### Critical Alerts (sofortige Benachrichtigung)

| Alert | Bedingung | Aktion |
|-------|-----------|--------|
| Service Down | neonfall.service inaktiv | Email + Restart-Versuch |
| Multiplayer Down | neonfall-multiplayer inaktiv | Email (nicht kritisch) |
| High Error Rate | >10% 5xx in 5min | Email |
| Disk Full | >90% disk usage | Email |
| DB Error | Prisma connection failed | Email |
| SSL Expiry | Zertifikat <14 Tage | Email (certbot timer) |

### Implementation

Uptime Kuma übernimmt HTTP-Monitoring + Alerts.
systemd übernimmt Service-Restarts (Restart=always).
Fail2ban übernimmt SSH-Brute-Force-Schutz.
